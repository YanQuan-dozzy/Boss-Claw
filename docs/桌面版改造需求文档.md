## 1. 背景与现状

当前仓库存在多份来源、不同形态的源码，结构混乱：

| 位置 | 内容 | 状态 |
| --- | --- | --- |
| `desktop-app/` | `main.cjs` + `preload/app.cjs` + `renderer/index.html` + `package.json` | **未完成的骨架**：`index.html` 引用了不存在的 `app.js` / `styles.css` |
| `旧版本/source/` | Chrome 扩展源码（含完整测试） | 历史版本 |
| `旧版本/chrome-extension/` | 早期 Chrome 扩展 | 历史版本 |
| `旧版本/desktop-app/` | 另一版 Electron 雏形 + `学习逻辑/` | 历史版本，参考价值高 |
| `旧版本/desktop-bridge/` | 本地桥接（server.js / cli.js / swift 解析器） | 历史版本 |
| `旧版本/skills/` | `jobclaw` skill | 历史版本 |
| 根目录 `README.md` 等 | 项目说明、构建元数据 | 维持现状 |

**结论**：需以 `desktop-app/` 为目标位置，从零**完全重写**为参考图所示的统一 Electron + React 应用。

## 2. 改造目标

1. 交付**单窗口、统一风格的 Electron + React 桌面应用**（`desktop-app/`），取代分散的多版本源码。
2. 布局严格对齐参考图：**左侧固定功能侧栏**为全局框架；**「工作台」页三栏**（侧栏 + 消息进度 + 内置浏览器）作自动投递主界面，其余页**双栏**（侧栏 + 功能页）。
3. **自动辅助能力必须实现**：本期交付手动闭环（加入任务 → 进度展示 → 执行日志 → 失败恢复 → 手动投递）；**全自动**为后续阶段目标。
4. 内置浏览器默认加载 **BOSS 直聘**；本期 webview + 地址栏 + 联动 + 手动投递 + **登录态持久化**，页面自动识别投递交后续阶段。
5. 支持**浅色 / 深色**主题切换（跟随 antd 主题）。
6. 技术栈：**React + TypeScript + Vite + Ant Design + Zustand**（前端），Electron 主进程 CommonJS。
7. **OpenClaw 桥接后端实装**：用 **Node 重写跨平台**（替代仅 macOS 可编译的 swift 解析器），含 OCR、日报、本地文件、任务恢复。
8. **AI 接入真实 LLM API**：职业画像、岗位匹配、沟通草稿调用真实模型；设置中**预设多家（OpenAI / DeepSeek / 通义 / 智谱）+ 自定义 OpenAI 兼容端点**。
9. 打包：**Windows 优先**（electron-builder），macOS / Linux 后续补。

## 4. 应用整体架构

### 4.1 进程模型
- **主进程**（`electron/main.cjs` 或经 Vite 打包）：单 `BrowserWindow`，`contextIsolation: true`、`nodeIntegration: false`、`webviewTag: true`；承载 OpenClaw Node 桥接子进程与 LLM 代理 IPC。
- **预加载**（`preload/app.cjs`）：`contextBridge` 暴露安全 IPC（外部链接、本地数据、桥接状态、LLM 代理、webview 会话持久化）。
- **webview 预加载**（`preload/webview.cjs`）：内置浏览器 guest 页桥，向中栏回传页面信息（本期回传 URL/标题/“加入任务”事件，自动识别后续启用）。
- **渲染进程（React）**：`src/` 下 TSX，Vite 构建；路由、状态、主题用 Zustand + antd。

### 4.2 全局布局框架（所有页面共用）

```
┌──────────────────────────────────────────────────────────────┐
│  标题栏：JobClaw 桌面版 v2.0 ｜ 自动辅助·运行中 ｜ 浅色/深色   │
├──────────┬───────────────────────────────────────────────────┤
│          │                                                   │
│  功能侧栏 │            主内容区（按页面类型分栏）               │
│  (固定)   │                                                   │
│          │                                                   │
├──────────┴───────────────────────────────────────────────────┤
│  状态栏：桥接已连接 · Electron · 已投递/已跳过/待确认           │
└──────────────────────────────────────────────────────────────┘
```
- 标题栏左：品牌 + 版本 + 状态 Pill；右：主题切换。
- 侧栏：固定宽约 200px，7 入口 + 底部桥接状态。
- 状态栏：桥接状态、Electron 版本、投递统计。

## 5. 功能侧栏入口（已确认，按顺序）

## 6. 各功能页面详细需求

### 6.1 首页（双栏）
- 运行状态卡片（自动辅助、桥接、LLM 配置状态）。
- 快捷入口：新建投递方向、打开工作台、导入简历、打开 OpenClaw。
- 最近动态（近 5 条投递/异常）。

### 6.2 工作台（三栏 —— 核心投递页）
- **左栏**：功能侧栏。
- **中栏（消息与进度）**：
  - 顶部任务选择 / 新建任务（基于投递方向模板）。
  - 任务进度条 + 阶段标签（整理/匹配/排序/沟通/投递）。
  - 执行日志流（时间戳 + 级别 + 消息），实时滚动。
  - 单条岗位结果（成功/跳过/异常）+ 操作（重试/忽略）。
  - 控制：启动 / 暂停 / 停止。
- **右栏（内置浏览器）**：
  - `<webview>` 加载 BOSS 直聘（默认 `https://www.zhipin.com`），地址栏可用。
  - **岗位来源**：用户在浏览器打开岗位 → 点“加入任务”→ 中栏记录该岗位（本期）。
  - **登录态持久化**：BOSS cookie/会话存本地，下次免登录。
  - **本期投递交互**：中栏选岗位 → 浏览器跳转 → AI 草稿预填沟通框 → 用户点发送（半自动）；**全自动**为后续阶段。
  - 与中栏联动：中栏选岗位 → 浏览器跳转对应页。

### 6.3 简历中心（双栏）
- 导入 PDF / DOCX / TXT；**Node 解析提取文本**，保留可编辑原文。
- 列表展示、预览、编辑、删除。
- “AI 生成职业画像”（调用真实 LLM，画像可编辑，存本地）。

### 6.4 投递方向（双栏）
- 勾选岗位方向（多选）、改搜索词、调优先级、加自定义方向。
- 保存为任务模板，供“工作台”创建任务选用。

### 6.5 任务进度（双栏）
- 任务列表：名称、关联方向、进度、阶段、结果。
- 单条岗位记录：状态、时间、异常原因。
- 失败恢复：重试 / 忽略 / 继续。
- 快捷跳“工作台”三栏界面。

### 6.6 OpenClaw（双栏）
- **Node 重写跨平台桥接后端**（替代 swift 解析器）：OCR、日报生成、本地文件读写、任务状态恢复。
- 桥接状态（已连接/未连接），可连接/重连。
- 能力开关 + 配置入口 + 日志查看。

### 6.7 设置（双栏）
- 外观：浅色/深色/跟随系统（antd 主题）。
- **LLM**：预设多家（OpenAI / DeepSeek / 通义 / 智谱）+ 自定义 OpenAI 兼容端点（Base URL + Key + 模型名），存本地；缺失时相关功能提示配置。
- 桥接：连接配置、重连。
- 数据：导出/导入、清空缓存。
- 关于：版本、协议、文档链接。

## 7. 内置浏览器规范
- Electron `<webview>`（主进程 `webviewTag: true`）。
- 默认 `https://www.zhipin.com`。
- **登录态持久化**：webview 会话持久化到本地，免重复登录。
- 本期范围：webview + 地址栏 + 联动 + 手动/半自动投递 + “加入任务”事件回传；自动识别投递交后续。
- 外部链接经 `shell.openExternal`。

## 8. 技术栈与目录结构

### 8.1 技术栈
- **Electron**（沿用 `^31`），**React 18 + TypeScript + Vite**，UI 用 **Ant Design 5**，状态用 **Zustand**（含 persist 中间件接 localStorage）。
- 本地数据：**localStorage**（Zustand persist），零依赖。
- LLM：预加载脚本代理请求真实 LLM（OpenAI 兼容，预设多家+自定义）。
- 桥接：**Node 重写跨平台**（依赖如 `pdf-parse` / `mammoth` 解析简历，`tesseract.js` 等做 OCR）。
- 打包：**electron-builder**，Windows 优先。

### 8.2 `desktop-app/` 目标目录结构


## 10. 自动辅助 / 自动投递实现边界

**AI 调用**：职业画像、岗位匹配排序、沟通草稿均调真实 LLM（OpenAI 兼容，预设多家+自定义，设置配密钥）。无密钥时降级提示，不阻断其他流程。

**本期（阶段 3）必须交付**：
- 基于“投递方向”模板创建任务（工作台）。
- **岗位来源**：浏览器打开岗位 → “加入任务” → 中栏记录（本期）。
- 进度展示、执行日志、单条岗位结果。
- 控制：启动/暂停/停止；异常（登录异常/安全验证/对象不确定/发送未确认）→ 立即暂停交用户。
- 失败恢复：重试/忽略/继续。
- 内置浏览器：webview + 地址栏 + 联动 + 半自动投递（AI 草稿预填 + 用户发送）+ 登录态持久化。

**后续阶段目标**：全自动（页面自动识别 + 自动发送）。本期架构为全自动预留接口（webview 注入脚本、任务状态机）。

遵循原设计原则：用户主动控制、本地优先、最小必要、真实信息优先、不对抗安全措施。
